# travel-screen v1.0.0

首个公开版本：一个用 **Spring Boot 3 + Java 21** 做的个人旅行足迹可视化大屏。

单文件前端、零外链、纯本地渲染 —— 不需要地图 Key、不需要 CDN、不需要构建前端。

## 直接跑起来

```bash
java -jar travel-screen-v1.0.0.jar
# 打开 http://localhost:8388/
# 演示账号  demo@travel.cn / Demo@2026
```

只要 JDK 21，零配置。默认用本地 H2 文件库，数据落在当前目录。

或者用 Docker：

```bash
git clone https://github.com/Makezx/travel-screen.git
cd travel-screen && docker compose up -d
```

## 这个版本里有什么

### 地图与可视化
- **2D 中国地图**：行程城市点亮、按到访次数热力着色、路线飞线、城市标签
- **3D 地图**：echarts-gl `geo3D` 挤出视图，自动旋转 + 城市光柱 + 飞线流光
- **全量离线底图**：覆盖全国 **369 个地级市** + 34 个省级行政区 + 南海诸岛十段线。
  底图由独立端点 `GET /api/geo` 提供并缓存一天，与行程数据接口解耦
- 核心 KPI、花费排行 Top 10、消费结构、年度足迹、同行伙伴、待办行程滚动条
- 照片墙：按城市自动匹配行程照片

### 记账与分摊
- Excel 式行内编辑后台，行程与明细支持 xlsx 导入 / 导出
- **AA 分摊精确到分**，余数精确分配不丢不凑
- **最少转账数清账**：直接输出「谁该给谁多少钱」，不用自己算

### 协作
- 三层模型：团队 → 活动 → 行程
- 活动角色四档 `OWNER > CO_OWNER > EDITOR > MEMBER`，含授予链校验（低角色无法提权）
- 大屏可按活动/团队切换，游客可查看分享出去的大屏

### 其他
- AI 行程规划（可选，需自配 `AI_API_KEY`，默认关闭）
- Docker one-command 启动，数据与照片走具名卷持久化
- 本地 H2 零配置；生产可切 MySQL（`prod` profile）

## 几个刻意的取舍

| 决定 | 原因 |
|---|---|
| 前端就一个 HTML 文件，没有 npm/webpack/vite | 改一行刷新即生效，不需要构建链 |
| 不引任何 CDN，ECharts 与地图数据全部本地内嵌 | 内网/离线可用，且不受外部服务变更影响 |
| 不接第三方地图服务 | 不用申请 Key、不用管配额，矢量数据在仓库里 |
| 城市名支持自然写法 | 填「恩施」「阿坝」「伊犁」就能命中原自治州全称，不必写全 |

## 部署到公网前请注意

- **必须改掉默认管理员密码**（`ADMIN_USER` / `ADMIN_PASS`），默认值仅供本地体验
- 不要提交 `travel-auth.json` / `travel-secret.key` / `.env` / 数据库文件
- 请放在 HTTPS 反代之后

细节见 [SECURITY.md](https://github.com/Makezx/travel-screen/blob/main/SECURITY.md)。

## 已知限制

- 3D 视角目前是**省级**挤出图，2D 已是地级市全量
- 权限模型定位是协作隔离，不是对抗攻击者的安全边界；公网部署建议在反代层再加一道访问控制
- 单实例内存态限流，重启后清零
